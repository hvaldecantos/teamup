# PRD: Normalized Mean Scorer

## Problem Statement

The existing `MaxDifferenceScorer` evaluates partition quality by comparing raw attribute sums across groups. This approach has a critical flaw: attributes with larger numeric ranges dominate the score. For example, "weight in kg" (50–100) will overpower "pH level" (6–8) simply because its numbers are bigger — even if both attributes are equally important for balance.

Users who want to balance entities across attributes with different scales get misleading scores and suboptimal partitions.

## Solution

Introduce a new scorer — `NormalizedMeanScorer` — that first normalizes each attribute globally to a [0, 1] scale before evaluating group balance. Balanced is defined as: groups have equal attribute means. The score is derived from the difference between the highest and lowest group means across attributes.

To support different use cases, three strategies for combining per-attribute differences are provided: maximum, average, and root mean square (RMS). The maximum strategy is the default, making it a drop-in upgrade from `MaxDifferenceScorer`.

## User Stories

1. As a developer, I want attribute values normalized before scoring, so that attributes with larger ranges don't disproportionately influence the partition quality score.

2. As a developer, I want "equal groups" defined by equal attribute means (not sums), so that groups of different sizes are still evaluated fairly.

3. As a developer, I want to choose the maximum difference across attributes as the score, so that the worst imbalance drives the optimization — matching the conservative spirit of `MaxDifferenceScorer`.

4. As a developer, I want to choose the average difference across attributes as the score, so that every attribute contributes equally to the final score.

5. As a developer, I want to choose the RMS difference across attributes as the score, so that larger imbalances are penalized more heavily than smaller ones.

6. As a developer, I want the max strategy to be the default, so that I can adopt `NormalizedMeanScorer` with minimal configuration.

7. As a developer, I want the normalization range to be computed globally across all entities in all groups, so that the scale is consistent and not distorted by a single group's distribution.

8. As a developer, I want zero-variance attributes (all entities share the same value) to produce zero contribution to the score, so that constant attributes don't cause errors or noise.

9. As a developer, I want convenience subclasses for each strategy, so that I can reference them by name without remembering string method names.

10. As a developer, I want the scorer to raise clear errors on empty groups or empty attribute lists, consistent with `MaxDifferenceScorer`, so that misconfiguration is caught early.

11. As a developer, I want the scorer to fit the existing `Scorer` abstract interface, so that it can be plugged into the `Partitioner` without any changes to the orchestration layer.

12. As a developer, I want the scorer to support any number of groups, so that it works for both 2-team and N-team partitioning.

## Implementation Decisions

### New Module: `NormalizedMeanScorer`

Added to `scorer.py` alongside `MaxDifferenceScorer`. Implements the `Scorer` interface.

**Algorithm:**

1. Collect all entities from all groups; compute global `min` and `max` per attribute.
2. Normalize each entity's value: `(value - global_min) / (global_max - global_min)`. If the range is zero, all normalized values are set to `0.0`.
3. Compute each group's mean of normalized values per attribute.
4. For each attribute, compute `max_group_mean - min_group_mean`.
5. Combine per-attribute differences using the chosen strategy.

**Combination strategies (prototype snippet encoding the decision):**

```python
if self.method == "max":
    return max(differences)
elif self.method == "average":
    return sum(differences) / len(differences)
elif self.method == "rms":
    return (sum(d ** 2 for d in differences) / len(differences)) ** 0.5
```

**Convenience subclasses** (thin wrappers, no new logic):
- `MeanMaxDifferenceScorer` — `method="max"`
- `MeanAverageDifferenceScorer` — `method="average"`
- `MeanRMSDifferenceScorer` — `method="rms"`

### No Changes to Existing Modules

The `Scorer` abstract interface, `Partitioner`, `PartitionerBuilder`, `Entity`, and `Partition` are unchanged. `NormalizedMeanScorer` is a pure addition.

## Testing Decisions

### Test Philosophy
- Test only external behavior: what score comes out for a given partition and attributes.
- Do not test intermediate normalized values directly; infer correctness from the final score.
- Use hand-computed expected values derived from the normalization and combination formulas.

### Modules to Test

**`NormalizedMeanScorer`** — comprehensive coverage:
- Instantiation with all three methods; default is `"max"`
- Invalid method raises `ValueError`
- Single group (score is always 0)
- Balanced groups (same values → score 0)
- Unbalanced groups (full range → score 1.0)
- Multiple entities per group
- Multiple attributes with each combination method (`max`, `average`, `rms`)
- Three or more groups
- Zero-variance attribute (constant values → 0 contribution)
- Floating point values
- Error cases: empty groups, empty attributes, empty group, missing attribute

Convenience subclasses are verified only for instantiation (`method` property check).

### Prior Art
- Existing `MaxDifferenceScorer` tests in `tests/test_scorer.py` serve as the template for structure and naming conventions.
- All scorer tests use inline `Entity` construction; no shared fixtures.

## Out of Scope

- **Weighted attributes**: all attributes are treated equally. A future `WeightedNormalizedMeanScorer` could accept per-attribute weights.
- **Custom normalization ranges**: global min/max from the current partition is the only supported strategy. Clamping to predefined domain ranges is not supported.
- **Changes to `PartitionerBuilder` defaults**: the default scorer remains `MaxDifferenceScorer`. Changing the default is a separate decision.
- **Performance optimizations**: normalization is recomputed on every `score()` call. Caching is not implemented.

## Further Notes

The `NormalizedMeanScorer` with `method="max"` is semantically the closest to `MaxDifferenceScorer` but operates on normalized means rather than raw sums. It will generally produce scores in [0, 1], making scores comparable across datasets with different attribute scales — a property `MaxDifferenceScorer` does not have.
